# Тир 2 — ключи и первая проверка плана

Здесь заводятся ключи всего стека и делается первый прогон `verif` — тройной проверки твоего файла тремя ИИ разных компаний.

## Зачем

Самая дорогая ошибка — не та, которую не заметил, а та, которую сам себе обосновал.

Когда просишь один чат «покритикуй мой план», он видит и план, и твои доводы — и достраивает твою же логику: соглашается и подкрепляет. `verif` устроен иначе: один и тот же файл читают три ИИ трёх разных компаний, порознь, не зная ни автора, ни его объяснений.

Пять шагов механики:

1. Три чтения в изоляции — у каждого свой поиск, чужих выводов никто не видит.
2. Один формат ответа — вердикты сравнимы между собой.
3. Итог по худшему, а не по среднему: одна ветка сказала «ненадёжно» — таков и общий вердикт.
4. Слепой судья: арбитр разбирает находки, не зная, чья каждая (метки A / B / C).
5. Пачка вопросов к тебе — решает человек, а не конвейер.

## Как выглядит

![Канвас плана на трёх опорах, механические руки выдёргивают опоры](https://github.com/beCyborg/jadlis-hub/blob/main/docs/img/01-verif-01.webp?raw=1)

Конвейер одного прогона (тег `jadlis-verif--v2.0.0`):

1. **Твой файл** — план, ресерч или документ.
2. **Три ветки порознь** — Codex (`gpt-6-astra`), Claude (Fable 5), Grok (`grok-4.6`); без Grok — две ветки.
3. **Сведение по худшему** вердикту.
4. **Арбитр Fable 5** — источники скрыты: A / B / C.
5. **Пачка вопросов к тебе** → решаешь ты.

## Как поставить

Скопируй блок ниже в Claude Code — он всё сделает сам.

```text
Ты — установщик. Выполни ровно эти шаги и ничего сверх них:
1. Bash: claude plugin marketplace add https://github.com/beCyborg/jadlis-hub
2. Bash: claude plugin install jadlis-search@jadlis --config BRAVE_API_KEY=<мой ключ Brave> --config FIRECRAWL_API_KEY=<мой ключ Firecrawl>
3. Bash: claude plugin install jadlis-verif@jadlis
4. Скажи мне: «Плагины стоят, ключи уехали в Связку ключей. Полностью перезапусти
   Claude Code — не /reload-plugins, у jadlis-search свои MCP-серверы — и вызови /jadlis-search:keys».
```

Тот же путь руками, теми же командами:

1. **Заведи два обязательных ключа.** Brave — https://api-dashboard.search.brave.com, нужен тариф **Search**. Firecrawl — https://firecrawl.dev/app/api-keys, ключ вида `fc-…`.
2. **Подключи маркетплейс и поставь `jadlis-search`.** `claude plugin marketplace add https://github.com/beCyborg/jadlis-hub`, затем `claude plugin install jadlis-search@jadlis --config BRAVE_API_KEY=… --config FIRECRAWL_API_KEY=…`. Ключи уезжают в Связку ключей, в файлы не попадают; поменять потом — `/plugin configure jadlis-search@jadlis`.
3. **Поставь `jadlis-verif`:** `claude plugin install jadlis-verif@jadlis`.
4. **Перезапусти Claude Code полностью.** `jadlis-search` тянет MCP-серверы, они поднимаются на старте сессии; `/reload-plugins` для таких плагинов не применяется.
5. **Вызови `/jadlis-search:keys`.** Скилл покажет, что уже есть, и примет остальное. Нужен только `jadlis-verif` — научные ключи пропусти, вернёшься к ним перед тиром 3.

Первый прогон — на своём же файле:

```text
/verif --file <путь к твоему плану>
```

Плана под рукой нет — сойдёт любой черновик решения. Синтетический кусок для пробы:

```text
План: перевести рассылку на собственный домен.
Допущения: у провайдера есть бесплатный тариф до 10 000 писем; переезд не рвёт старые ссылки.
Шаги: 1) купить домен, 2) перенести список, 3) отключить старый сервис в тот же день.
```

Опционально, но заметно усиливает результат:

- **Codex CLI** (подписка ChatGPT) — обязательная ветка: без него плагин не ставится.
- **Grok CLI** (подписка Grok) — третья ветка, $0 сверх подписки. Без него — режим на двух ветках; в тире 3 отваливаются ещё каналы `grokweb` и `twitter`.

Без обоих CLI прогон не падает: остаётся одна ветка Claude, но пропадает главное — независимость чтений. Вердикт одной ветки читать как «мнение», а не как проверку.

## Как пользоваться

Три сценария, три команды:

```text
/verif --file План.md                    # полный прогон: три ветки → арбитр → вопросы
/verif --file Ресерч.md --report-only    # только отчёт, без вопросов и правок
/verif --file Док.md --only fable        # одна ветка: быстрый черновой проход
```

Что важно знать по ходу:

- Ветки идут параллельно и отчитываются по мере готовности — первый вердикт виден раньше остальных.
- Тип файла (`plan` / `research` / `doc`) определяется сам; можно задать явно `--type`.
- Все артефакты прогона ложатся в vault, в `AI/verif/` — json каждой ветки, сведённый вердикт и файл решений.
- Качество проверки зависит от того, что ты дал: допущение, выписанное явно, — мишень; растворённое в тексте — мина, которую не найдёт никто.

## Границы и стоимость

Чего `verif` не делает:

- Не ревьюит код и диффы — для этого `/code-review`.
- Не исследует тему с нуля — это тир 3 (`jadlis-research`, `jadlis-science-research`).
- Не проверяет одну фразу или дату: тридцать секунд обычного поиска дешевле.
- Не принимает решений: он приносит находки, отвечаешь на вопросы ты.

Что стоит денег:

| Что | Сколько | Обязательно |
|---|---|---|
| Brave Search API, тариф Search | ≈$0.005 за запрос | да |
| Firecrawl | по кредитам тарифа | да |
| Подписка ChatGPT (Codex CLI) | по тарифу подписки | да — ветка Codex обязательна |
| Подписка Grok (Grok CLI) | $0 сверх подписки | нет — ветка Grok |

Одна ветка не может висеть дольше 600 000 мс — дальше её обрывает таймаут, а вердикт собирается из выживших. Если ветка молчит, она помечается сбоем, а не «согласием».

## Ключи: где они лежат

Единый принцип: **ключ вводится один раз и живёт в Связке ключей macOS, а не в файлах.** Два класса:

| Класс | Примеры | Где лежит | Кто пишет |
|---|---|---|---|
| A — ключи MCP-серверов плагина | `BRAVE_API_KEY`, `FIRECRAWL_API_KEY`, `REDDITAPIS_KEY`, `YOUTUBE_API_KEY` | Связка ключей, запись Claude Code `Claude Code-credentials` → `pluginSecrets` | Claude Code: `/plugin configure jadlis-search@jadlis` или `claude plugin install jadlis-search@jadlis --config KEY=…` |
| B — ключи скриптов и `curl`-блоков | научные источники, Exa, Yandex, Places, контактные почты | Связка ключей, обычная запись: служба `jadlis`, учётная запись = имя ключа | скилл `/jadlis-search:keys` — значение принимается на stdin, в командную строку не попадает |

Читает их одна точка — `scripts/secret.sh` внутри плагина `jadlis-search`. Порядок разрешения:

1. Переменная окружения `$KEY`, если задана.
2. Связка ключей: служба `jadlis`, учётная запись `KEY` (записи со старой службой `jadlis-research` тоже читаются).
3. `pluginSecrets` из записи `Claude Code-credentials` (затем `Claude Code-credentials-*`, если профилей несколько).
4. `.credentials.json` в каталоге настроек — для платформ без Связки ключей.
5. `settings.json → env` — старая рельса; скилл `keys` предлагает свернуть её и удалить значения из файла.

Ничего не нашлось — скрипт молча возвращает ошибку, а канал или слой деградирует. Ключей он не печатает никогда: только имена, длины и источник.

> [!note] Окно «security хочет получить доступ»
> При первом чтении записи `Claude Code-credentials` macOS может спросить разрешение — нажми **«Разрешить всегда»**. Иначе ключи класса A будут видны MCP-серверам, но не Bash-скриптам. Записи класса B создаются так, что окна не вызывают.

Почему не иначе: `settings.json` лежит открытым текстом с правами 644 и попадает в бэкапы; shell-профиль (`~/.zshenv`) десктопный Claude Code для MCP-серверов не читает; менеджеры паролей с подпиской есть не у всех. Связка ключей есть у всех и одна на все инструменты.
